## Annahmen
- `Retry-After`: je IP bis zum Fensterende; je Hof fest die Bestätigungsfrist (spätestens dann ist ein Platz frei; kein weiteres Lesen, während jemand den Hof flutet); je Adresse keiner (8a verlangt nur „Satz wie b)“).
- Reihenfolge der Bremse: erst Adresse und Hof (nur lesen), dann IP zählen — wer an Adresse oder Hof scheitert, verbraucht nichts vom Kontingent seiner IP.
- Code `GESAMT_GEAENDERT` als Wort in Route und Formular (wie `WARENKORB_GEAENDERT`): `src/lib/kasse.ts` liegt außerhalb der Dateigrenze.
- `serverBetrag` wird beim Rendern geleert, sobald `kassenStand` (Korb, Zahlart) abweicht (React-Muster „Zustand bei geänderten Werten zurücksetzen“, kein Effekt).
- Bekannte Lücke: Adresse und Hof werden ohne Sperre vor der Transaktion gezählt; gleichzeitige Anfragen von mehreren IPs können die Grenze knapp überschreiten (begrenzt durch die Grenze je IP; Reihenfolge nach 8a vorgegeben).
- Grenzberührungen: Kopfkommentar von `src/server/abholfenster.ts` außerhalb von `imAbholfenster` (ein Satz zur Vorprüfung); neuer Export `kassenStand` in `checkout-form.tsx`.
